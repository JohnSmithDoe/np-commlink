# i18n — bilingual, German default, extractable keys

**Read before adding any key family** — composing a key at the call site is what makes `--clean`
delete it.

`@ngx-translate/core` **v18**, provider API only: the root is
`provideTranslateService({lang, fallbackLang, loader: provideTranslateHttpLoader({prefix, suffix})})`
in `main.ts`. **`TranslateModule` no longer exists**, so a component imports the standalone
**`TranslatePipe`** and a spec off the shared kit calls `provideTranslateService()`. Importing the
pipe instead of a module is also what makes an unused i18n import visible: the compiler reports
`NG8113` on a pipe it cannot find in the template, which a module import always hid.

**Bilingual, German default.** Flat dotted keys in `public/i18n/{de,en}.json`; all kitchen-bot keys
are namespaced under `household.` to avoid collisions with timetracker keys. TS-side keys must be
`marker('…')`.

The UI language is a `language` on the eager `settings` slice, applied by `SettingsEffects` through
**`LanguageService`** (`@shared/util`, the exact sibling of `ThemeService` and for the same reason —
`commlink`/`cash`/`trackplay` read the locale and may not import `settings`), which owns the three
globals a language touches: the translate bundle, `dayjs.locale`, `<html lang>`.

**`<html lang>` is also applied at module scope**, from `bootLanguage()`. Left to `apply()` alone it
was not corrected until `npc-settings` came out of IndexedDB, so the shell's first paint declared
whatever `index.html` shipped — `lang="en"` over German labels, i.e. the wrong screen-reader voice and
hyphenation dictionary for the default language. The static attribute now matches `bootLanguage()`'s
default, and the module-scope write (`app.providers.ts` imports the module, so it evaluates before
`bootstrapApplication`) closes the window for an English user too rather than merely re-betting on
German. Different reason from the rest: nothing in *our* code reads `<html lang>` — the browser does,
at first paint.

**Switching restarts the app.** Money/score/date render through _pure_ pipes whose output is cached on
input identity, and `LOCALE_ID` is a provider that cannot be re-resolved, so a live switch would leave
the screen half-formatted. The restart awaits `DatabaseService.settled()` so it cannot overtake the
save effect and drop the choice. `LOCALE_ID` + the first bundle come from a synchronous `localStorage`
mirror (`bootLanguage()`), because a provider cannot await IndexedDB; the settings doc stays the
source of truth and the restart is what keeps them from ever being observed apart.

**Every display format is locale-named, never a German literal:** `date:'short'`/`'shortTime'`/
`'fullDate'` in templates, `localizedDate`/`localizedLongDate`
(`@shared/util/formatting/date-format.utils`) for the dayjs call sites. That module owns dayjs's
plugin *and* its locale packs because both fail silently — `format('L')` without `localizedFormat`
returns the literal `"L"`, and `dayjs.locale('de')` without the pack keeps the previous locale.

**Page titles are the one namespace keyed by page, not by domain:** `page-title.<domain>[-<page>]`
(`page-title.cash-rules`, `page-title.household-shopping`, `page-title.office-time-settings`). A title
is read by the shell as much as by its page, so it lives in one flat namespace — which retired
`officetime.` (≠ the `office-time` domain), the `cash.`/`trackplay.` title prefixes, and tasks' title
hiding under `household.`.

## The composed-key problem, and why `--clean` works again

`i18n:extract` once had `--clean` removed because running it deleted live keys. That was damage
control on wrong reasoning: **the keys were never dynamic** — every affected family is a closed,
finite compile-time set, invisible to the extractor only because it was _composed at the call site_
instead of written as `marker(...)` literals. The measurement: the extractor found 461 keys against
581 committed, so `--clean` would have deleted **120** across four families.

Five composition sites became declared consts:

| keys | was composed at | became |
| --- | --- | --- |
| 60 | `deck.utils` `resolveLabels` | `labels` on each catalog entry |
| 38 | `deck.utils` `resolveChrome` | `DECK_CHROME_LABELS: Record<Theme, DeckChrome>` |
| 11 | `deck.facade` `configuredModules` | `DECK_MODULE_LABELS: Record<AppModule, Marker>` |
| 8 | `commlink.page` `metricKey` | `metricKey` on each catalog entry |
| 3 | `edit-recipe-dialog.component.html` | `UNIT_LABEL_KEYS: Record<ItemUnit, Marker>` |

**The shape rule: a plain `Record<TUnion, Marker>` annotation**, which is what enforces exhaustiveness
— the only property this needs. Values go straight to `translate`, which takes a `string`, so
`as const satisfies …` is ceremony. **Key strings stay whole — never mirror the dotted path in nested
objects:** a `{ household: { unit: { ml: marker('household.unit.ml') } } }` tree states the prefix twice
with nothing deriving one from the other, and one tree spanning `deck.*`/`household.*`/`cash.*` would
have to live in `@shared/model`, which Sheriff bars from naming domain vocabulary. Nesting is for a
real axis only (the theme, in `DECK_CHROME_LABELS`). Avoid the bare-`marker(...)`-statement style too:
it makes keys visible without tying them to the union, so a new member silently lacks a label.

**Three load-bearing flags:**

```json
"i18n:extract": "ngx-translate-extract --input ./src -o 'public/i18n/{de,en}.json' --clean --sort --format-indentation '  ' --trailing-newline --format json"
```

- **Both outputs** — the original bug. `ngx-translate-extract` has no locale discovery; it writes
  exactly the paths it is given, so `en.json` had been maintained entirely **by hand**.
- **`{de,en}.json`, quoted.** The tool expands braces itself, and quoting guarantees *it* does rather
  than the shell (macOS `/bin/sh` expands braces, Linux `dash` does not) — removing the difference
  between a laptop and the Codeberg runner.
- **`--format-indentation '  '`, never the `-fi` alias.** With more than one output, yargs reads `-fi`
  as clustered `-f -i` and the run dies with `Unknown format: json,json`. Measured; do not "simplify".
- **`--format-indentation` + `--trailing-newline` are what stop the churn.** The extractor defaults to
  tab indent and no trailing newline while prettier owns these files. Without them a merge-extract
  differed by **1164 lines**; with them it is byte-identical to a file `prettier --check` passes.

**The acceptance test:** `pnpm run i18n:extract` → `git diff --exit-code public/i18n/` is clean.
Composing a key again is exactly what silently makes it prunable. A **CI freshness gate** was decided
against for the same reason the flags exist — _one artifact, two writers_ is always a bug in the
making.

## The `@shared` domain-vocabulary gate

An audit of the `@shared` kernel (2026-07-24, adversarially verified; 28 of 34 findings confirmed;
closed 2026-07-25) found one root cause: the merge namespaced all kitchen-bot keys under one domain prefix (then `grocery.`, now `household.`)
and re-domained the shared components, but never re-homed the strings or de-domained the shared
_types_. Both halves are closed — the shared surfaces moved onto neutral namespaces (`categories.*`,
`item-list.*`, `toast.*`, `a11y.back`) and the kernel model is domain-blind.

**The class is gated by `commlink/i18n-key-ownership`**, at `error` over `src/app/**/*.{ts,html}` with
specs excluded. One rule covers both directions: it resolves the owning folder from the filename, so
`@shared` may name no domain prefix at all and a domain may name no *other* domain's. This is exactly
the class Sheriff is structurally blind to — it checks import edges, and `'household.a11y.back' |
translate` is a string, not an edge.

It used to be twelve generated `no-restricted-syntax` blocks, one per domain plus `@shared`, and that
shape carried a live footgun: flat config *replaces* a rule's options rather than merging them, so a
selector added to one block was silently dropped wherever a later block set the same rule id. A rule
**id** cannot be shadowed that way.

> **Trap worth knowing.** The rule needs TWO node types. A quoted key is a `Literal` in TypeScript but
> a `LiteralPrimitive` in an Angular template, so a `Literal`-only selector silently passes every
> template — and templates are where most of this class lived. The first cut did exactly that and let
> a deliberately re-injected leak through. **Always verify a new gate by re-introducing the thing it
> is supposed to catch.**
